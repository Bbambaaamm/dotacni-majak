# Detail: version dates alongside other deadlines (#401)

`GrantCallVersion.submission_open_at` / `submission_close_at` are source-version values, not independently evidenced `GrantDeadline` rows. If the version has either date and no normalized application deadline, detail API adds an `APPLICATION_WINDOW` with `evidenceId: null`, even when another deadline (for example `PROJECT_FINISH`) is normalized. A normalized `APPLICATION_WINDOW` suppresses the fallback to avoid implying another application period. This does not fill a missing half of a partially normalized `APPLICATION_WINDOW`; that remains a separate data-completeness question.

The detail marks the fallback as a summary without its own attached evidence, and tells users to verify the exact submission deadline with the provider. If only a normalized `APPLICATION_CLOSE` or `APPLICATION_OPEN` exists, the opposite non-null version date is now retained as a separate, explicitly unattributed opening or closing row. A normalized `APPLICATION_WINDOW` or both normalized boundary rows remain authoritative for display and suppress this fallback; a missing version date is never invented. The source's precision and offset are preserved and no independent timezone is assigned. Real D1/API regression covers both partial directions and the fully normalized case; the existing synthetic D1/API open call plus desktop/mobile browser test covers the separately evidenced closing and unattributed opening with axe/reflow. No absence of a deadline is interpreted as unlimited submissions.
