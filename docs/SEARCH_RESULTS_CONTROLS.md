# Výsledky vyhledávání — globální stav a dostupnost termínu (#400)

`/hledat` načítá z `GET /api/search` nejprve 20 výsledků v pořadí relevance; další stránky načte uživatel tlačítkem. Volitelný stav (`OPEN`, `PLANNED`, `ANNOUNCED`) a dostupnost termínu (`KNOWN` = uveden, `UNKNOWN` = neuveden/NULL) filtrují všechny odpovídající aktivní výsledky na serveru před stránkováním v přímé i ontologické fázi. Přepnutí stavu či termínu znovu načte první stránku; pevné možnosti nejsou odvozené z načtených výsledků. Poskytovatel zůstává filtrem pouze nad dosud načtenou sadou; přepnutí řazení podle nejbližšího uvedeného termínu nepřepočítává relevanci ani způsobilost. Neuvedený termín (UNKNOWN) neznamená prošlý termín a při řazení je na konci. Přehled a aktivní odstranitelné filtry uvádějí příslušný rozsah.

Nativní rozbalovací panel `<details>` se ovládá klávesnicí a na mobilu nevyžaduje hover. Žádné filtry nepřidávají tvrzení o financování ani způsobilosti. Na chybu API a prázdný index se zachovává původní fail-closed stav; E2E scénář používá skutečné API, D1 a seed výzvy, nikoli mock response.

`GET /api/search?intent=…` vrací `nextCursor` (neprůhledný pro klienta, `null` na konci). Následující požadavek pošle stejný normalizovaný záměr, stejný volitelný `status` a `deadline` a `cursor`; výchozí `limit=20`, povolený rozsah 1–50. Chybný limit, cursor, stav nebo dostupnost termínu vrací 400 (`INVALID_LIMIT` / `INVALID_CURSOR` / `INVALID_STATUS` / `INVALID_DEADLINE`); `CLOSED`, `ALL`, prázdné i opakované hodnoty filtru jsou nepovolené. Nepřítomný status zachovává původní aktivní hledání. Nedostupná DB vrací 503 bez citlivých údajů. Pořadí je deterministické podle FTS rank a ID verze: nejdřív přímé shody, potom širší ontologické shody bez opakování přímých. Cursor je svázán se záměrem, velikostí stránky, stavem a dostupností termínu, není autentizační token ani snapshot databáze. Při souběžné změně indexu mohou další stránky obsahovat nové/posunuté záznamy; klient duplicitní ID verze při připojování zahodí. Po chybě další stránky zůstává načtená sada viditelná a lze pokus zopakovat. Počet načtených výsledků není celkový počet shod.

Tento navazující úzký slice neuzavírá #400: globální facety, serverový filtr poskytovatele, chronologický filtr termínu, serverové řazení, bezpečně doložené finance filtry a jejich UX/E2E zůstávají otevřené. Obecné konvence pro jiné API endpointy patří do #545, nikoli do tohoto search-specifického kontraktu.
