# Výsledky vyhledávání — ovládání načtené sady (#400)

`/hledat` načítá z `GET /api/search` nejprve 20 výsledků v pořadí relevance; další stránky načte uživatel tlačítkem. Stav, poskytovatel a dostupnost termínu jsou filtry pouze nad dosud načtenou sadou; přepnutí řazení podle nejbližšího uvedeného termínu nepřepočítává relevanci ani způsobilost. Neuvedený termín (UNKNOWN) zůstává odlišný od prošlého a při řazení je na konci. Přehled a aktivní odstranitelné filtry výslovně uvádějí toto omezení.

Nativní rozbalovací panel `<details>` se ovládá klávesnicí a na mobilu nevyžaduje hover. Žádné filtry nepřidávají tvrzení o financování ani způsobilosti. Na chybu API a prázdný index se zachovává původní fail-closed stav; E2E scénář používá skutečné API, D1 a seed výzvy, nikoli mock response.

`GET /api/search?intent=…` vrací `nextCursor` (neprůhledný pro klienta, `null` na konci). Následující požadavek pošle stejný normalizovaný záměr a `cursor`; výchozí `limit=20`, povolený rozsah 1–50. Chybný limit nebo cursor vrací 400 (`INVALID_LIMIT` / `INVALID_CURSOR`); nedostupná DB vrací 503 bez citlivých údajů. Pořadí je deterministické podle FTS rank a ID verze: nejdřív přímé shody, potom širší ontologické shody bez opakování přímých. Cursor je svázán se záměrem a velikostí stránky, není autentizační token ani snapshot databáze. Při souběžné změně indexu mohou další stránky obsahovat nové/posunuté záznamy; klient duplicitní ID verze při připojování zahodí. Po chybě další stránky zůstává načtená sada viditelná a lze pokus zopakovat. Počet načtených výsledků není celkový počet shod.

Tento navazující úzký slice neuzavírá #400: globální facety, serverové filtry/řazení nad celou množinou, bezpečně doložené finance filtry a jejich UX/E2E zůstávají otevřené. Obecné konvence pro jiné API endpointy patří do #545, nikoli do tohoto search-specifického kontraktu.
